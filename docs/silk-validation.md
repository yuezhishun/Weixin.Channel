# SILK 解码验证

验证日期：2026-11-07。产品继续使用 `DrAbc.SilkCodec 1.0.0`，不随产品引入 Node 或本机 SILK 解码库。

## 验证目标与参考

语音转 WAV 必须保留音频内容，不能只断言文件非空或长度正确。为此使用以下三条路径比较：

1. 官方微信插件所使用的 `silk-wasm 3.7.1` 编码和解码包装。
2. `silk-wasm` 上游提交 `2793875764ad98245c177ac496eb5b7100a71038` 所带的 SILK SDK 1.0.9 C 源码，逐包调用 `SKP_Silk_SDK_Decode`，输出 24 kHz、单声道、PCM16。该探针仅用于验证，不属于发布依赖。
3. 产品指定的纯 C# `DrAbc.SilkCodec 1.0.0`，同样输出 24 kHz PCM，再包装 WAV。

合成输入为一秒 440 Hz 与 880 Hz 双音、首尾渐变，分别以 8/12/16/24 kHz 输入官方编码器。四份输出均带微信使用的 `0x02 + #!SILK_V3` 前缀，按 little-endian 包长度分帧，并非只验证标准 SILK 文件头。这些合成音频不含第三方录音，测试夹具保留相应 SILK 和 C SDK 参考 PCM。

## 结果

所有合成样本输出长度均为 48,000 字节。24 kHz 输入的纯 C# 与底层 C SDK 输出**逐字节一致**，SHA-256 为：

```text
805f820127a4f62e0d0603cd3f4399779fb09ad4950db70a66438022ca591c7d
```

低采样率路径涉及重采样算法及群延迟差异，不能要求未经对齐的 PCM 逐字节相同。相对底层 C SDK，合成样本对齐后的验证结果为：

| 输入采样率 | 波形相关系数 | 信噪比 |
|---|---:|---:|
| 8 kHz | 0.999450 | 29.43 dB |
| 12 kHz | 0.999468 | 29.56 dB |
| 16 kHz | 0.999864 | 35.46 dB |
| 24 kHz | 1.000000 | 逐字节一致 |

另使用解码器作者仓库的 `tests/SilkCodec.NET.Tests/assets/free.silk` 作临时真实语音核验：输出 314,880 字节；与 C SDK 参考补偿五个采样点延迟后，相关系数为 0.996495，信噪比 21.50 dB。该外部录音仅用于本地调查，不随本项目发布。

Windows x64 与 WSL Ubuntu 24.04 Linux x64 均使用 SDK `11.0.100-rc.3.26522.148` 实际运行。纯 C# 对上述四个合成样本和真实语音的输出哈希在两平台完全一致。

## 调查中纠正的假设

最初将 `silk-wasm` 包装器输出直接作为逐字节真值，比较出现明显差异。当时“纯 C# 解码可能错误”的判断并不充分：进一步用底层 C SDK 比较，发现 24 kHz 完全一致，低采样率差异主要为重采样延迟，而 `silk-wasm` 包装器自身也与该逐包 SDK 路径不同。

因此没有通过降低产品测试断言掩盖失败，也没有更换已经批准的依赖。正式验证分别检查 24 kHz 的严格参考输出，以及涉及重采样时的内容一致性、长度和 WAV 格式；初始包装器差异保留为参考实现差异，不声称两种包装的所有 PCM 均相同。

本次采样验证不代表所有损坏帧、内部采样率切换或真实微信客户端均已验证。损坏输入必须安全失败并保留原始 SILK；真实微信语音收发仍按 [验收记录](acceptance.md) 单独执行。

## 本次扫码账号的真实手机录音

2026-11-07，用户在本次独立扫码的微信会话录制了“微信渠道语音验收，中文和数字一二三”。正常Claim获得服务端转写，按官方优先级没有下载语音附件；因此没有将该正常路径记作无转写的语音回退验收。

随后仅对这条消息的语音item，在Windows x64调用当前渠道库既有`Media.DownloadAsync`下载、解密及转换，并保留同次响应解密后的微信SILK。结果为8.66秒、24kHz、单声道、PCM16 WAV；用户播放回传的WAV后确认内容、语速、音高正常且无明显杂音。WSL Linux x64使用同一库对保存的同份SILK离线解码，与Windows下载转换所得WAV逐字节一致：

- SILK SHA-256：`cf07d97c0321d7389a9df5c9b4c5c75bfbd179e80263983377f6c9dcddeb402b`
- WAV SHA-256：`02b57d09a430a51ef616e6e5bf6ba2fea219d959ff516a477017bdc7f32e43a8`

真实录音及验证helper仅保存在ignored的`artifacts/live`中，不作为公开测试fixture或NuGet内容发布。这项结果证明该真实样本能由当前纯C#解码器处理，不扩大为所有微信语音格式均已验证。
